prose about this project. It inlines or links other dependencies' own pre-written usage-rules files

configuration are removed on each sync. It cannot author FOUND-13's file. That file is hand-written.

<threat_model>

## Trust Boundaries

| Boundary                                      | Description                                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------------------------------- |
| third-party GitHub Action to repository token | Actions authored elsewhere execute in CI with whatever token scope the workflow grants      |
| documentation to reader                       | A coding agent acts on what the documentation claims, without verifying it against the code |

## STRIDE Threat Register

| Threat ID  | Category               | Component                                                     | Severity | Disposition | Mitigation Plan                                                         |
| ---------- | ---------------------- | ------------------------------------------------------------- | -------- | ----------- | ----------------------------------------------------------------------- |
| T-01-SC-03 | Tampering              | unpinned third-party actions in CI                            | high     | mitigate    | Pin every action to a version or commit; workflow-level read-only token |
| T-01-BI-16 | Tampering              | CI restating gate steps instead of invoking the alias         | high     | mitigate    | Invoke `mix check`; assert the workflow does not list the steps         |
| T-01-BI-17 | Tampering              | aggregated usage-rules block drifting from the dependency set | medium   | mitigate    | Regenerate in CI and fail on an uncommitted difference                  |
| T-01-ID-03 | Information Disclosure | documentation claiming capabilities the code lacks            | medium   | mitigate    | Only document what exists; state the known-broken capability plainly    |

### Mitigation detail

- T-01-SC-03: this repository ships no network surface and handles no user input, so CI is its
  realistic external attack surface. An action referenced by a floating branch can change under the
  repository at any time and runs with the workflow's token. Pinning plus a read-only workflow-level
  permission bounds both the change and the blast radius.
- T-01-BI-16: a gate that CI runs differently from the local alias is two gates that agree only by
  coincidence. The alias's own comment already prescribes invoking it, and the acceptance criteria
  assert the workflow calls it rather than enumerating its steps.
- T-01-BI-17: the sync tool treats the configuration as the source of truth and removes packages from
  the target that are absent from the configuration, so the aggregated block goes stale silently after
  a dependency change. Regenerating in CI and failing on a difference converts that into a red build.
- T-01-ID-03: the existing `CLAUDE.md` documents three verifiers that do not exist and three stale
  dependency versions, and PROJECT.md instructs treating every claim in it as unverified. Writing a
  second document with the same failure mode would double the problem, so every claim here is written
  against the code as it stands and the one known-broken capability is stated rather than described as
  working.

</threat_model>
