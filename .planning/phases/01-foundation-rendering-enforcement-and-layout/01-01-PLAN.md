<objective>
Prove the whole Phase 1 apparatus on one thin vertical slice: capture the AST a transformer wrote,
render it as formatted Elixir source through a real mix task, commit it as a golden file carrying its
own size budget, and gate that budget in `mix check`. End to end, on one generated module, before
anything is widened.

Purpose: every later phase's human-approval step (method step 4) is blocked until a developer can see
what AshCommanded generates. This plan makes that visible for the first time and at the same moment
establishes the measurement the rewrite is judged by.

Output: `mix ash_commanded.dump`, an AST-capture hook and explicit source-location metadata on the
shared codegen seam, one committed golden, and a budget test that runs on every CI leg.
</objective>

LAYER 1, the capture seam. In `AshCommanded.Commanded.Transformers.BaseTransformer.create_module/3`,

cannot crash an ordinary compile. Keep the return value `:ok` and the existing `@spec` unchanged. Do
not touch any of the nine call sites.

LAYER 2, the mix task. Create `Mix.Tasks.AshCommanded.Dump` at `lib/mix/tasks/ash_commanded.dump.ex`
with `use Mix.Task`, a `@shortdoc` and a `@moduledoc` documenting the invocation shape
`mix ash_commanded.dump <DslModule>` per D-05. For the tracer, implement only the default bare
invocation plus `--only <GeneratedModule>`. The `--beam`, `--write` and golden-diff behaviours are
plan 02's expansion and are out of scope here. The `run/1` sequence is:

1. `Mix.Task.run("compile")` so Ash, Spark and Commanded load through the fast cached path.
2. Resolve the CLI argument to a module using `Module.safe_concat/1` and `Code.ensure_loaded/1`.
   `Module.safe_concat/1` is required rather than `Module.concat/1`: the unsafe form mints a brand new
   atom from arbitrary CLI input, which is the atom-exhaustion class recorded as T-01-DOS below. Exit
   non-zero through `Mix.raise/1` with a message naming the argument when either step fails.
3. Read the target's own source path from `Module.__info__(:compile)[:source]`, so no path argument is
   ever needed and a bare module name suffices.
4. Create the public named ETS table, set `:capture_ast?` to true, set
   `Code.compiler_options(ignore_module_conflict: true)` to suppress the redefinition warning, then
   call `Code.compile_file/1` on the source path. This re-runs the whole Spark transformer pipeline
   for that file in-process, so every `create_module/3` call along the way captures.
5. Unset the flag immediately afterwards inside an `after` block, so a raise during compilation cannot
   leave capture switched on for later builds.
6. Select captured entries whose module name sits under the target module's own namespace, or exactly
   the `--only` module when that flag is given.
7. Render each captured AST with `Macro.to_string/1` then `Code.format_string!/1`, reusing
   `render_generated.exs`'s `safe_format/1` rescue-and-return-raw fallback verbatim so AST that
   round-trips imperfectly still prints instead of losing the output.
8. Print the rendered source through `Mix.shell()`.

LAYER 3, the golden. Run the task against `AshCommanded.TestSupport.Parity.Widget` with
`--only AshCommanded.TestSupport.Parity.Commands.CreateWidget`, read the output, and commit it verbatim
to `test/golden/parity_widget/AshCommanded.TestSupport.Parity.Commands.CreateWidget.golden`. Its first
line must have the exact form `# gsd-budget: clause_max=N module_lines=N`, with N replaced by the
measured values for that render. One golden file per generated module, foldered per fixture, per D-10
and the `specifics` note in CONTEXT.md.

LAYER 4, the budget gate. Create `test/ash_commanded/golden_budget_test.exs`. It globs
`test/golden/**/*.golden` and for each file: parses the `gsd-budget` header into `clause_max` and
`module_lines`; parses the body below the header with `Code.string_to_quoted!` passing `columns: true`
and `token_metadata: true`; measures every `:def` and `:defp` node's span by subtracting the node's own
`meta[:line]` from its `meta[:end][:line]` and adding one, reading both numbers directly off the node
metadata. Do NOT postwalk descendants taking min and max of `:line`: bare literals carry no line
metadata and that approach undercounts, per RESEARCH.md "Open Question 2". Measure `module_lines` as
the body's line count excluding the header. Then assert that the measured clause span is at most the
declared `clause_max`, that the measured module line count is at most the declared `module_lines`, and
that the declared `clause_max` is at most 10, which is FOUND-06's absolute ceiling and D-03's global
cap. A golden whose first two lines include a `gsd-staged-until-phase:` marker is exempt from the
ceiling assertion only; plan 02 introduces staged goldens for not-yet-rewritten components, so write
that exemption branch now rather than making plan 02 reopen this file's assertion logic. Every failure
message must name the golden's path together with both the measured and the declared number.

Write the budget test's assertions BEFORE producing the golden in layer 3, confirm the test fails
against a deliberately wrong header, then correct the header. The gate must be shown to bite before it
is trusted.

<threat_model>

## Trust Boundaries

| Boundary                                  | Description                                                                                    |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------- |
| developer CLI to `mix ash_commanded.dump` | A module name arrives as a string from `System.argv` and becomes an atom and a filesystem path |
| transformer AST to ETS to mix task        | Generated AST crosses the compile boundary through a public, unprotected named ETS table       |

## STRIDE Threat Register

| Threat ID  | Category          | Component                                   | Severity | Disposition | Mitigation Plan                                          |
| ---------- | ----------------- | ------------------------------------------- | -------- | ----------- | -------------------------------------------------------- |
| T-01-DOS   | Denial of Service | dump task argument handling                 | low      | mitigate    | Resolve the CLI argument with `Module.safe_concat/1`     |
| T-01-CE    | Tampering         | `Code.compile_file/1` in the dump task      | low      | accept      | Path comes from the developer's own compiled source tree |
| T-01-BI-01 | Tampering         | `test/ash_commanded/golden_budget_test.exs` | high     | mitigate    | Treat a zero-test run as failure; prove the gate bites   |
| T-01-BI-02 | Tampering         | `:capture_ast?` left enabled after a raise  | medium   | mitigate    | Unset the flag in an `after` block                       |

### Mitigation detail

- T-01-DOS: `Module.safe_concat/1` raises on an unknown atom instead of minting one, so arbitrary CLI
  input cannot grow the atom table without bound. Enforced by the acceptance criterion that greps the
  task source for `Module.safe_concat`.
- T-01-CE: the compiled path is derived from `Module.__info__(:compile)[:source]` on an
  already-compiled module in the developer's own tree, so running it is no more privileged than running
  `mix compile`. No control beyond the argument gate above.
- T-01-BI-01: a size gate that measures nothing is a control that does not exist. The `fails_when` on
  the budget-test command treats a zero-test summary as failure, and the acceptance criteria require
  the gate to be observed failing against a deliberately wrong header before it is trusted.
- T-01-BI-02: leaving the capture flag on would silently change what every later `mix compile` writes
  into ETS, so the flag is cleared in an `after` block that a raise cannot skip.

</threat_model>
