THE TWO HELPERS, on `AshCommanded.Resource.Transformers.BaseTransformer`, beside `create_module/4`.

`dsl_location/1` takes the DSL state and returns a location keyword list for `create_module/4`.
Read the DSL-using module's own source path from `Spark.Dsl.Transformer.get_persisted/2` under the
`:file` key. Spark persists that key for every extension at the moment the consumer writes `use
Ash.Resource` or `use Ash.Domain`, so it is available inside every `transform/1` without deriving
anything. Return the file (as a binary — the persisted value is already a binary but callers must
not assume) paired with line 1 when the key is present, and an empty list when it is absent. An
empty list is not a failure mode: `create_module/4` already documents empty as "fall back to
`Macro.Env.location(env)`", which is today's behaviour, so a DSL module without a persisted file
degrades to the status quo rather than handing `Module.create/3` a nil file.

`entity_location/2` takes a DSL entity and the DSL state and returns the same shape, but with the
entity's own declaration line instead of line 1. Obtain the line through the public accessor
`Spark.Dsl.Entity.anno/1` and `:erl_anno.line/1`. Do not pattern-match the `Spark.Dsl.Entity.Meta`
struct directly: its type is declared opaque in Spark, and matching it from outside is both a
Dialyzer opacity violation and a private-shape dependency. Guard the call with a check that the
entity actually carries the `__spark_metadata__` field, because `anno/1` deliberately emits an
`IO.warn` for entities that do not, and this library must not emit that warning during an ordinary
consumer compile. When there is no annotation, fall back to `dsl_location/1` so the file is still
correct and only the line degrades.

Both helpers are public, so both carry a `@moduledoc`-consistent `@doc` with an example and a
`@spec`, per this repository's Elixir conventions in `.claude/CLAUDE.md`. Neither may split or
concatenate a module name; the persisted file and the entity annotation are the only inputs, which

<threat_model>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| DSL author's source file to compiled artefact | A path read from Spark's persisted state is baked into every generated module's compile metadata and into consumer-visible stacktraces |
| generated module to consumer runtime | Errors from generated code surface in a consumer's own logs and error reporters, carrying whatever location this library attributed |
| transformer source to build gate | A call site left unwired is invisible unless something counts occurrences rather than files |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-01-ID-04 | Information Disclosure | absolute build-machine paths in generated modules' compile metadata | low | accept | Spark persists `:file` as the absolute path the compiler already records for every ordinary Elixir module, so generated modules gain no exposure hand-written modules do not already have; no new path data is introduced and nothing is emitted at runtime |
| T-01-BI-18 | Tampering | a `create_module` call site left on the three-argument form | high | mitigate | AST-based occurrence guard asserting a three-argument count of zero AND a four-argument count of at least nine, so it cannot pass by finding nothing |
| T-01-BI-19 | Tampering | attribution asserted by a test that never exercised it | high | mitigate | The end-to-end test asserts both that the fixture's path is reported and that the transformer tree's path is not, and derives the expected line from the fixture at test time rather than from a literal |
| T-01-BI-20 | Tampering | a Dialyzer finding escaping the ratchet by moving to a file the ignore list does not name | medium | mitigate | Task 3 asserts the exact total, skipped and unnecessary-skip counts rather than only that `mix dialyzer` exits 0 |
| T-01-DO-01 | Denial of Service | untrusted input reaching the location helpers | low | accept | Both helpers read only compile-time state: Spark's persisted file and an entity annotation captured at macro-expansion time. No caller-supplied value reaches them, and they run once per generated module during compilation, never at dispatch |
| T-01-SC-04 | Tampering | dependency supply chain | low | accept | This plan installs no package and changes no entry in `mix.exs` deps or `mix.lock`; `Spark.Dsl.Entity.anno/1` is a public accessor on a dependency already vendored and pinned. The package-legitimacy gate has nothing to audit here |

### Mitigation detail

- T-01-BI-18 and T-01-BI-19 are the same defect class this phase has now hit five times: a check
  that cannot be distinguished from doing nothing. Both mitigations are written as two-sided
  assertions — a positive and a negative, or a floor and a ceiling — because a one-sided assertion
  about generated code is satisfied equally well by correct wiring and by an empty search.
- T-01-BI-20 is a live consequence of WR-05 in `01-REVIEW.md`: dialyxir's ignore file matches by
  substring on the file field, so a finding that relocates escapes silently. Asserting the counts
  rather than the exit code is what makes the relocation visible.
