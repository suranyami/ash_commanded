roadmap asks for.

prose, because "prose gates decay once the approving human moves on". These are those checks.

plugin, phase-cited suppressions on the generators later phases rewrite, and a committed clone report.

THE NAMESPACE-DERIVATION DECISION, made here and not deferred. `Module.split` and `Module.concat`
appear 30 times across 12 files in `lib/`. Three of them are in `base_transformer.ex`'s

literal sense the rule asks for, because a generated module's parent namespace has no source other
than the DSL module's own name; Spark persists the resource module, not a namespace prefix, and
ARCHITECTURE.md records `ash_oban` doing exactly the same derivation legitimately. And a phase-cited
suppression is wrong because D-02 requires the cited phase to be live and incomplete, whereas this
site is permanent and no phase will remove it.

a permanent, visible exemption. Adopt a single named exemption: the marker comment
`# ash_commanded:namespace-derivation` placed immediately above the one blessed function that derives
a child namespace from a DSL module's own name. Both checks honour that marker, and both check test
suites assert that it occurs exactly once across `lib/`. That turns rewrite rule 11 into enforcement:
tricky name manipulation goes behind one named utility whose purpose is legible, and every other site
is a defect. Record this reasoning in `get_module_prefix/1`'s `@doc` beside the marker, so the next
reader is not left inferring it. Also apply the marker to `get_resource_name/1` only if the check
flags it; a `Module.split` terminating in `List.last/1` with no concatenation must not be flagged at
all, so it should need no marker.

| ---------------------------------------- | ----------------------------------------------------------------------------------------------------- |

| rule as prose to rule as gate            | A registered check that does not block is indistinguishable from an absent check until a defect ships |
