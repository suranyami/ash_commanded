<threat_model>

## Trust Boundaries

| Boundary                         | Description                                                                                       |
| -------------------------------- | ------------------------------------------------------------------------------------------------- |
| fresh render to committed golden | `--write` is the only blessed path by which machine output becomes a reviewed, committed artifact |
| developer machine to repository  | Rendered output can carry machine-specific absolute filesystem paths into a committed file        |

## STRIDE Threat Register

| Threat ID  | Category               | Component                                    | Severity | Disposition | Mitigation Plan                                              |
| ---------- | ---------------------- | -------------------------------------------- | -------- | ----------- | ------------------------------------------------------------ |
| T-01-BI-03 | Tampering              | `--write` becoming reflex                    | high     | mitigate    | Refuse on budget growth; detect bypass in the budget test    |
| T-01-BI-04 | Tampering              | staged-golden marker as an open escape hatch | medium   | mitigate    | Marker must cite a live phase; ratchet still applies         |
| T-01-BI-05 | Tampering              | text-diff test silently excluded everywhere  | high     | mitigate    | Exclusion is version-scoped in one literal, asserted by grep |
| T-01-ID    | Information Disclosure | absolute paths embedded in committed goldens | low      | mitigate    | Normalise absolute paths to repository-relative before write |

### Mitigation detail

- T-01-BI-03: golden files have one classic failure mode, which is `--write` becoming reflex, after
  which the golden records what happened rather than what was approved while every CI check stays
  green. The refusal on budget growth places friction exactly where judgement is needed, and the
  self-consistency assertions in `golden_budget_test.exs` catch a golden that was hand-edited or
  regenerated by some other path, bypassing the refusal entirely.
- T-01-BI-04: the staged marker exempts a golden from the absolute ceiling, which would be an
  unbounded escape hatch if unchecked. It is bounded two ways: the ratchet still forbids growth on a
  staged golden, and plan 05's citation test asserts the cited phase exists in the roadmap and is not
  already complete, so the marker expires with the phase that removes it.
- T-01-BI-05: a text-diff test excluded on every leg is a control that does not exist. The exclusion
  is computed from one canonical-version literal in `test/test_helper.exs` and the acceptance criteria
  grep for both that literal and the D-12 citation beside it, so the exclusion cannot quietly widen.
- T-01-ID: a committed golden containing a developer home directory both leaks a local path and makes
  the CI text diff permanently red. Paths are normalised to repository-relative before comparison or
  write, verified by a count-zero grep over the golden tree.

</threat_model>
