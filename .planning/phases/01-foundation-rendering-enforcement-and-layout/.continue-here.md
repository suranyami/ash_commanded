## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Post-merge gate blind to Elixir | The gate's language sniff covers Cargo/Go/Python/npm/Make/Justfile/Xcode but has no `mix.exs` branch, and neither `workflow.build_command` nor `workflow.test_command` is set. Both the build gate and the test gate therefore skip silently — a resuming agent will believe a wave was build- and test-verified when nothing ran. | blocking | Set `workflow.build_command` = `mix compile --warnings-as-errors` and `workflow.test_command` = `mix test` in `.planning/config.json`. Until then, run both at every wave close and paste the exit codes into the wave report. Waves 1 and 2a were verified this way (exit 0; 215 tests, 0 failures). |
| Resume-gate tag bound | `safe_resume_gate` bounds its plan-commit grep by `git describe --tags --abbrev=0`. This repo tags *releases*, not milestones: `v0.2.0` is dated Dec 2025 and sits 78 commits behind the v0.3 milestone start, so the gate surfaced the *previous* milestone's identically-numbered `01-01`..`01-06` commits as if they were partial work for this milestone's plans. Plan IDs recur every milestone, which is what makes the bound load-bearing. | advisory | Re-bound at the milestone-start commit (`160af7c` for v0.3), not the tag, and corroborate by checking the flagged commits predate the current plans' authoring commit (`00a7c7f`). |
| Gate verb invoked as `query` | Hook manifests carry a bare `check.query` string (e.g. `verify.schema-drift`). It must be invoked as `gsd_run check <query> <PHASE> --raw`. Invoking `gsd_run query <query>` returns a *usage error with exit 0*, which under a hook whose `onError` is `halt` is indistinguishable from a real gate failure — it nearly halted the phase on a UI gate in a library with no frontend. | advisory | Use only the `check` subcommand form specified in `execute-phase/steps/wave-post-gate-hooks.md`, and pass the phase number explicitly. |
