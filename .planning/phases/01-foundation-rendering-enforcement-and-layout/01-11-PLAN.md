<objective>
Make the CI matrix genuinely green on all three supported Elixir legs while removing the
shell-out antipattern from the project's gate.

Purpose: the first observed CI run (39367006559) proved the workflow executes, and surfaced two
real defects that presence-and-consistency review could not see. The 1.19.6 and 1.20.4 legs are
red for different reasons: the `mix check` alias shells out with `cmd MIX_ENV=test mix coveralls`,
which Mix 1.19 no longer parses through a shell, and Elixir 1.20's compiler emits six warnings in
project code, four of them inside modules generated by `GenerateAggregateModule`.

Output: a gate composed of direct Mix invocations with the environment chosen by the caller, no
project compiler warnings under 1.20, regenerated and human-approved goldens where generated
output legitimately changed, and an observed three-leg green run recorded as evidence.
</objective>

`mix usage_rules.sync --check` as its own step. Update the comments so they describe the new
composition and no longer claim a single alias restates the whole gate.

Update `AGENTS.md` and `README.md` to document the two commands and the separate parity step.
State plainly why the test invocation is separate: Mix aliases run in one environment, and
switching environments inside an alias requires a subprocess, which this project now refuses.

  <name>Task 3: resolve the four generated-code warnings at macro-expansion time</name>
  <files>lib/ash_commanded/resource/transformers/generate_aggregate_module.ex, test/golden/parity_widget/AshCommanded.TestSupport.Parity.WidgetAggregate.golden</files>
  <read_first>
    - `lib/ash_commanded/resource/transformers/generate_aggregate_module.ex` lines 350 to 380, the `execute/2` context map and its `Map.get(command, :metadata, %{})`
    - the same file lines 425 to 470, `process_command/7` and its `include_aggregate?`, `include_command?`, `include_metadata?`, `context_prefix` and static context

    - `test/golden/parity_widget/AshCommanded.TestSupport.Parity.WidgetAggregate.golden`, the committed render these changes must update
  </read_first>
  <action>
Resolve each warning at macro-expansion time, per rewrite rule 2, rather than suppressing it:

1. `metadata: Map.get(command, :metadata, %{})` — the generated command struct has no `:metadata`
   field, so this is dead. Emit `%{}` unless the command struct actually declares metadata, in
   which case emit the direct field access.
2. `include_aggregate?` always true — branch on the unquoted configuration while building the AST
   and emit only the `Map.put`, not an `if`.
3. `context_prefix` always nil — choose the key literal at expansion time and emit one expression.
4. `key in [] || ...` in `input/1` — the configured key list is empty at expansion time; emit the
   branch that actually applies, not a runtime membership test against a literal empty list.

Do not add `@compile {:nowarn_...}` or any suppression attribute. The rendered output must get
smaller or stay the same size; it must not gain anything whose only purpose is silencing the
compiler.

Regenerate the affected golden with the documented command (`mix ash_commanded.dump ... --write`)
and inspect the diff before committing. If any golden outside the parity widget aggregate changes,
stop and report: that means the edit reached a component this task did not intend to touch.
  </action>
