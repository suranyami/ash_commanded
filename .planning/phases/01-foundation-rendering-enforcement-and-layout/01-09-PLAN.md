<objective>
Delete two registered transformers that walk a DSL block and then ignore it, and stop three
documentation sites advertising DSL blocks the extension does not declare.

Purpose: `CollectParameterTransforms` and `CollectParameterValidations` each iterate a command's
`transform_params`/`validate_params` block and substitute a fixed literal list for whatever was
found, under a comment saying it is a minimal set "for testing purposes until DSL is fully
complete". `01-REVIEW.md` raised this as WR-01 and noted that, unlike every sibling generator with
known staged debt, neither carries a phase citation, so nothing tracks it.

Investigation before planning established the shape of the defect more precisely than the review
did, and the difference matters. The `command` entity declares `entities: []` — the
`transform_params` and `validate_params` blocks do not exist in the DSL at all, so the hardcoded
stub is unreachable rather than silently applied, and `command.transforms` is `[]` for every command
today. The live defect is therefore not wrong dispatch behaviour; it is two registered transformers
that look like they implement a feature, plus documentation in three places that tells a consumer
to write DSL the extension will reject. A third documented block, `transaction`, is in the same
position, and `CollectTransactionOptions` carries one dead branch for it while the rest of that
module does real work on options that genuinely are declared.

This is fixed now rather than staged because staging requires citing a live phase that owns the
rewrite, and no phase does: `transform_params` and `validate_params` appear nowhere in
REQUIREMENTS.md. A citation naming Phase 2 would pass `disable_phase_citation_test.exs` — Phase 2 is
live and incomplete — while describing work Phase 2's requirements do not contain. That is a
citation indistinguishable from a no-op, which is the exact defect class this phase exists to
eliminate, so it would be convenient rather than honest.

Output: the dead transformers gone, the dead branch gone, three documentation sites corrected, a
guard that fails when documentation advertises an undeclared block, and an honestly-owned deferral
for the wider documentation sweep.
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| documentation to consumer's code | A consumer writes DSL by copying the library's own documentation; a claim that outruns the code becomes a compile failure in their project, or worse, a silent assumption |
| DSL declaration to transformer | A transformer that reads a block and discards it breaks the contract that declaring something makes it happen |
| removed code to release | Deleting a registered transformer changes the extension's published transformer list, which is observable by anything introspecting it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-01-BI-22 | Tampering | a transformer that walks a DSL block and substitutes a fixed list | high | mitigate | Delete both; assert positively that the entity declares no nested entities, which is why they were unreachable |
| T-01-ID-06 | Information Disclosure | documentation advertising DSL the extension does not declare | medium | mitigate | Correct all three sites and add a guard that fails when a documented nested block is undeclared |
| T-01-BI-23 | Tampering | a guard that exempts itself by containing the text it polices | high | mitigate | Exclude the guard's own source and `.planning/` from the scan set; write the remedy in prose rather than in declaration form |
| T-01-BI-24 | Tampering | a phase citation naming a phase that owns no such work | medium | mitigate | Refuse the citation for the deleted transformers, and require the one deferral this plan does make to name a live requirement group that covers it |
| T-01-BI-25 | Tampering | deleting code that turns out to have contributed to generated output | medium | mitigate | Byte-for-byte golden comparison with a non-zero test-count assertion, run after the deletion |
| T-01-SC-06 | Tampering | dependency supply chain | low | accept | This plan installs no package and changes no entry in `mix.exs` deps or `mix.lock`. The package-legitimacy gate has nothing to audit here |

### Mitigation detail

- T-01-BI-22's severity is `high` not because the stub is currently reached — it is not, and that was
  established by investigation rather than assumed — but because a registered transformer whose body
  contradicts its own name is a trap for the next reader, and the next reader is the person who
  implements the real feature.
- T-01-BI-23 is the direct descendant of CR-02 in `01-REVIEW.md`, where a prose mention of a marker
  exempted the file containing it and the guard written to police that counted files rather than
  occurrences and so never fired. Both halves of that failure are pre-empted here explicitly.
- T-01-BI-24 is the threat that gap closure quietly becomes paperwork. The mitigation is that a
  deferral must name a requirement group that already exists, and the plan states the test for
  telling a real owner from a convenient one.
