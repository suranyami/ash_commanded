<objective>
Remove every remaining reason a test might not run, and prove the two claims the suite has never been
able to make: that generated modules are identical under `MIX_ENV=test` and `MIX_ENV=dev`, and that
no test's outcome depends on state another test left behind.

Purpose: `test_helper.exs` currently excludes two tags and pins `seed: 0`. The fixed seed means
order-dependence can exist indefinitely without ever surfacing, and the tag exclusions mean nine
tests have never run. Both are mechanisms for a test not to fail, which is what this phase exists to
remove.
Output: a two-line test helper, a per-test Commanded application helper, a dual-environment parity
fixture and its check script, and direct-call tests for every generated module kind.
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| test process → Commanded application registry | A Commanded application registers a named process. Two tests sharing that name share an event store, which is a shared-state boundary inside the VM. |
| `:dev` compile path → library build | `elixirc_paths(:dev)` admits `test/support/parity` into the ordinary development build. Anything placed there is compiled by every `mix compile` a contributor runs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-01-16 | Tampering | Shared Commanded application name across tests | medium | mitigate | Each test starts its own application under a name derived from `System.unique_integer([:positive])`, never from the file or module, with its own InMemory store stopped in `on_exit`. Asserted directly by the second router test, which proves it cannot observe the first's record. |
| T-01-17 | Denial of Service | `test/support/parity` compiled under `:dev` | medium | mitigate | The parity directory is narrow by construction and contains only an `Ash.Resource` and `Ash.Domain` with no test-framework reference. A test-only reference there would break `mix compile` for every contributor; the zero-count grep gate and the explicit `MIX_ENV=dev mix compile` check both guard it. |
| T-01-18 | Repudiation | Removal of the default tag exclusions | low | accept | Nine previously-excluded tests begin running and may fail. That is the intended outcome, not a regression: an excluded test is a test whose result nobody has ever seen. The acceptance criteria require the test-count delta to be explained rather than absorbed. |

</threat_model>
