claims to be: the three surviving module-creation knobs, all six load-check stub branches, and the

against that router passes and proves nothing.
Output: seven files in `lib/` with no environment branch, no load-check fallback, and no console
print.

<threat_model>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| generated router → command dispatch | Before this plan, a fallback router could be generated that accepted every command and dispatched none. That module sat exactly where dispatch authorization and routing decisions are made. |
| log output → operator / log sink | The snapshot store's rescue previously wrote an inspected exception straight to stdout, bypassing every log level, filter and redaction the consuming application configures. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-01-06 | Spoofing | `generate_main_router_module.ex` stub `dispatch/1` returning `{:ok, command}` | high | mitigate | Delete both stub branches so the only router that can be generated is one built on `use Commanded.Commands.Router` with real dispatch handlers. A module that reports success for every command it never routed is indistinguishable from a working router to its caller and to its tests; removing it is the mitigation. Verified by a negative grep for the hand-written dispatch clause plus a positive count of two router `use` sites. |
| T-01-07 | Information Disclosure | `snapshot_store.ex` rescue writing `inspect(e)` to stdout | medium | mitigate | Route through `Logger.error/1` (D-09) so the consuming application's configured log level, backends, filters and redaction apply. An inspected exception can carry aggregate state; stdout honours no redaction policy. |
| T-01-08 | Tampering | `generate_commanded_application.ex` silently skipping application generation | medium | mitigate | Remove the load-check gate so the application module is always generated. A silently-absent Commanded application means projectors are never supervised, which fails open (events unprocessed) rather than loudly. |
| T-01-09 | Denial of Service | Bare `rescue e ->` in `snapshot_store.ex` swallowing `ArgumentError` from a missing ETS table | low | accept | Explicitly deferred by D-09 to the snapshot store rewrite (SNAP-01..03, Phase 4). Recorded here rather than fixed opportunistically, and carried into the SUMMARY so Phase 4 inherits it as a known item, not a rediscovery. |

</threat_model>
