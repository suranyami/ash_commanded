<objective>
Put the gate list behind a pull request: a GitHub Actions workflow that fans `mix test` and
`mix compile --warnings-as-errors` across the three supported Elixir/OTP pairs and pins the slow
gates — format, Credo, Dialyzer, docs, coverage and cross-environment parity — to a single primary
cell. Then sync Spark's and Ash's own usage rules into the repository so an agent working on this
library is told how Spark expects transformers and verifiers to behave.

Purpose: `.github/` does not exist in this repository. Everything Phase 1 built is currently enforced
only by a developer remembering to run `mix check`. This plan is what makes it enforced.
Output: one workflow file, two synced upstream rule files, and a documented pointer to them.
</objective>

    Create `.github/workflows/ci.yml` from scratch. There is no existing workflow to preserve and no
    reusable workflow to inherit.

    **Triggers.** Run on `pull_request`. Whether to also run on push to `main` is explicitly yours to
    choose (CONTEXT.md, Claude's Discretion); if you include it, use a `concurrency` group keyed on
    the ref with `cancel-in-progress: true` so a rapid push sequence does not queue redundant runs.

    **Least privilege.** Declare a top-level `permissions` block granting `contents: read` and nothing
    else. The workflow reads the repository, runs checks and reports status; it publishes nothing,
    comments nothing and needs no token scope beyond read. Do not reference `secrets` anywhere — this
    phase's CI has no legitimate use for one, and an unused secret reference is an attack surface with
    no benefit.

    **Job 1 — matrix.** Fan `mix test` and `mix compile --warnings-as-errors` across three
    Elixir/OTP pairs (D-20). The primary cell is pinned by D-20 to Elixir 1.18 on OTP 27, matching
    `core`'s runtime exactly; the other two cover Elixir 1.19 and 1.20 (REPO-04's declared support
    window). Resolve each version's OTP pairing against the official Elixir compatibility table at
    implementation time rather than carrying a guess — the pairings beyond the pinned primary cell are
    yours to choose, and a pair that is not actually supported produces a confusing red cell.
    Set `fail-fast: false` so one failing cell does not hide the others. Steps: checkout,
    `erlef/setup-beam`, restore a dependency cache keyed on the OS, the cell's Elixir and OTP versions
    and the `mix.lock` hash, then `mix local.rebar --force` (D-25), then `mix deps.get`, then the
    compile and test steps.

    **Job 2 — gates, primary cell only.** One job on Elixir 1.18 / OTP 27 running the slow gates
    once: format check, Credo, Dialyzer, docs build, coverage and the cross-environment parity check.
    Invoke `mix check` rather than listing the steps (D-23) — the alias already runs the REPO-05 gate
    list in order and CI restating it is exactly the drift the alias exists to prevent. If coverage is
    not part of the alias, add `mix coveralls` as a separate step and make it report-only: no
    threshold, no failure on a low number (D-18). D-17 deliberately deleted tests that could not fail,
    so the coverage number is expected to move before it climbs, and gating on it now would gate on
    the phase's own honesty.

    Credo runs at default strictness. Do not add `--strict`: D-21 records that promoting every
    readability check to a failure would fire on the two oversized modules Phases 4 and 6 are already
    scheduled to decompose, and `work/core`'s stricter setting is the deliberate exception, not the
    model here.

    **PLT cache.** Cache the `priv/plts` directory that `mix.exs`'s `plt_file` option names, keyed on
    the `mix.lock` hash plus the primary cell's Elixir and OTP versions. This is what makes D-20's
    "one PLT to build and cache instead of three" concrete — building it three times would dominate
    the run.

    **Action pinning.** Pin every third-party action to a released major version tag
    (`actions/checkout@v4`, `erlef/setup-beam@v1`, `actions/cache@v4`). Do not reference a mutable
    branch. Record in the SUMMARY that pinning to a full commit SHA is the stronger posture and is a
    candidate for a later hardening pass; a major tag is the ecosystem norm and is what this phase
    commits to.

    **Timeout.** Give each job a `timeout-minutes` sized from Plan 01-07's measured `mix check`
    wall-clock time with headroom for a cold PLT build, rather than leaving the six-hour default.

<threat_model>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| pull request → CI runner | A workflow triggered by `pull_request` executes repository code on GitHub-hosted infrastructure. The privileges that job holds are the blast radius of any code a contributor can propose. |
| third-party GitHub Action → CI runner | `actions/checkout`, `erlef/setup-beam` and `actions/cache` run with the job's full privileges. A compromised or re-tagged action inherits them. |
| upstream dependency docs → repository | `mix usage_rules.sync` copies Markdown published by the `ash` and `spark` packages into this repository, where agents and contributors will read it as guidance. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-01-23 | Elevation of Privilege | `.github/workflows/ci.yml` job token scope | high | mitigate | Declare a top-level `permissions` block of `contents: read` and nothing else, rather than inheriting the repository default, which on many repositories is write. The workflow publishes nothing and comments nothing, so read is sufficient. Asserted by a grep for the permissions block plus a zero-count grep for any secret reference. |
| T-01-24 | Tampering | Third-party GitHub Actions | high | mitigate | Every action is pinned to a released major version tag and none to a mutable branch, asserted by a negative grep against branch-style references. Full commit-SHA pinning is the stronger posture and is recorded in the SUMMARY as a candidate hardening pass rather than silently skipped. |
| T-01-25 | Information Disclosure | CI logs | medium | mitigate | The workflow consumes no secret, so there is nothing in the job environment to leak into a log. This is enforced structurally rather than by log redaction: `grep -c 'secrets\.'` must return 0. |
| T-01-26 | Tampering | Synced upstream usage rules read as authoritative guidance | low | accept | The files are copied from the `ash` and `spark` hex packages already declared and locked in `mix.lock`, so they carry the same provenance as the code those packages ship — no new supply-chain surface beyond `T-01-SC`. They are committed unmodified so a re-sync diff is meaningful, and the synced versions are recorded. |
| T-01-27 | Denial of Service | Unbounded CI job duration | low | mitigate | Each job declares `timeout-minutes` sized from the measured `mix check` wall-clock time with headroom for a cold PLT build, rather than inheriting the six-hour default. `concurrency` with `cancel-in-progress` bounds redundant queued runs if push triggers are enabled. |

</threat_model>
