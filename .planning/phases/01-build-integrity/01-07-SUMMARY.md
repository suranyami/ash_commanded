## Decisions Made

- Fixed both compiler-warning root causes at their source (projector clause pruning; event-handler action-type dispatch) rather than suppressing either — the orchestrator explicitly authorized the first; the second was outside the plan's stated `files_modified` but required by the plan's own unconditional "warnings-as-errors exits 0 in both `:dev` and `:test`" success criterion, so treated as a Rule 3 blocking-issue fix.

- Did not rename `Error.is_error?/1`/`is_error_result?/1` despite the naming-convention finding — both are public API with real call sites (`command_action_mapper.ex`, `test/commanded/error_handling_test.exs`); Phase 6 already owns decomposing `Error`, so renaming now would force a second breaking change.
- Ran `mix check`'s `test` step in a `cmd MIX_ENV=test mix test` subprocess rather than making the whole alias `:test`-preferred — Dialyzer has no `:ex_unit` application in its PLT, so running the full alias under `:test` (which adds `test/support` to `elixirc_paths`) made Dialyzer raise spurious `unknown_function` findings against ExUnit macros.
